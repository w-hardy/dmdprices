# dmdprices package audit

Audited against the Posit Claude skills vendored into `.claude/skills/`
(`r-package-development`, `testing-r-packages`, `cli`, `cran-extrachecks`,
`lifecycle`, `critical-code-reviewer`). Date: 2026-06-30.

> **Caveat:** no R toolchain was available in the audit environment, so nothing
> here was verified with `devtools::check()` / `devtools::test()`. Findings are
> from static analysis. Run `devtools::document()`, `devtools::test()` and
> `devtools::check()` after applying changes. Items marked **[applied]** were
> low-risk and changed in this branch; **[recommended]** items need a live R to
> verify and were left for the maintainer.

## Summary

The package is in good shape: tidyverse style, base pipe throughout, no
`%>%`, no `TODO`/dead code, every exported function has `@return` + `@examples`,
and a thorough behaviour test suite (~2,360 test LOC). The improvements below
are mostly about (a) the project's own "always use cli, never bare `stop()`"
rule being violated in two files, (b) the test suite ignoring the snapshot
guidance, and (c) a handful of CRAN-readiness gaps.

## High priority (recommended)

### 1. `R/nhscii.R` — bare `stop()` ×6, violating the mandatory cli rule
CLAUDE.md: *"always use `cli::cli_abort()` … Never use bare `stop()`."* Offending
lines: `nhscii.R:73, 82, 94, 166, 173, 215`. Convert to `cli::cli_abort()` with
inline classes, e.g.

```r
cli::cli_abort("{.arg {arg}} must be a single non-missing value.")
cli::cli_abort(c(
  "{.arg from_year} is not a known financial year.",
  "i" = "Use one of {.val {valid_years}}."
))
```

**Paired test change (required):** `tests/testthat/test-nhscii.R:37-57` asserts
exact message text via `expect_error(regexp = …)`. Switching to `cli_abort`
changes the rendered text, so migrate those four assertions to one
`expect_snapshot(error = TRUE, { … })` block (per the testthat skill) and run
`devtools::test()` to record the snapshot. *This is why it was not auto-applied
here — the snapshot must be generated by a live R run.*

### 2. `R/nhscii.R` — internal helpers not `.`-prefixed
`validate_scalar()` (`:71`), `normalize_fin_year()` (`:77`),
`build_index_levels()` (`:104`) break the CLAUDE.md "internals prefixed with `.`"
convention (the rest of the package is consistent, e.g. `.canonicalise_unit`).
Rename to `.validate_scalar()` etc. and update call sites.

### 3. `tests/` — snapshot guidance ignored (no `_snaps/` directory)
The `r-package-development` and `testing-r-packages` skills say: for errors use
`expect_snapshot(error = TRUE)`, for warnings use `expect_snapshot()`, not
`expect_error()/expect_warning()` on message text. There are **~21** message-text
assertions that should be snapshots, concentrated in
`test-dmd_dose_optimise.R` (e.g. `:64, 203, 794, 1004, 1052, 1131, 1147, 1431`)
and `test-nhscii.R:37-57`. Three hand-rolled
`withCallingHandlers(... muffleWarning)` warning-collectors
(`test-dmd_dose_optimise.R:1068, 1246, 1282`) are also textbook
`expect_snapshot()` cases. Migrating these makes the full cli output reviewable
and removes brittleness.

### 4. `cran-comments.md` missing
Required for CRAN submission (`usethis::use_cran_comments()`). Add a "Method
References" note pointing at the PSSRU manual (already cited via `\doi{}`) and
noting dm+d is a public NHS dataset. *(Only relevant if CRAN submission is
planned — the package is currently GitHub-only.)*

## Medium priority (recommended)

### 5. `lifecycle` deprecation version is inconsistent
`R/dmd_dose_optimise.R:491, 730` call `lifecycle::deprecate_warn("0.6.0", …)`
for the `objective = "both"` deprecation, but `DESCRIPTION` is `Version: 0.5.0`
and `NEWS.md` header is "(development version)". Decide the next release version
and make the `when` string, `DESCRIPTION`, and the NEWS header agree. Also run
`usethis::use_lifecycle()` to add the standard infra
(`@importFrom lifecycle deprecated`, badge SVGs) which is currently absent.

### 6. `~70` `expect_true()/expect_false()` calls should be specific expectations
The skill says prefer expectations that produce a real diff on failure. Worst
offenders in `test-dmd_dose_optimise.R`:
- `expect_true(grepl(…))` / `expect_true(any(grepl(…)))` → `expect_match()`
  (`:164, 166, 348, 369, 839, 914, 979, 1128, 1211`).
- `expect_true(a <= b)` / `>=` → `expect_lte()` / `expect_gte()`
  (`:276, 912, 930, 945, 980`).
- `expect_true(is.na(x))` → `expect_equal(x, NA_real_)` (`:646, 1518`).
- `test-dmd_load.R:63` `expect_true(inherits(…))` → `expect_s3_class()`.

### 7. Tests rely on ambient (file-level) state
`test-dmd_dose_optimise.R:1` and `test-dmd_price_lookup.R:33` define
`db <- .fake_dose_db()` at file top level, used inside many `test_that()`
blocks — violates the skill's "self-sufficient tests" rule and breaks
single-test runs. Move the constructor call inside each test (repetition is
explicitly acceptable).

### 8. Coverage gaps
- `dmd_load()` happy path: only error branches are tested; no test loads a fake
  CSV folder through the public function and checks the resulting `<dmd_db>`.
- `print.dmd_db` / `format.dmd_db`: untested — good `expect_snapshot()` targets.
- `run_dmd_price_lookup` / `run_dmd_dose_optimise` / `run_inflate_nhscii`:
  untested; the `system.file() == ""` branch can be snapshot-tested and the
  launch mocked with `local_mocked_bindings(runApp = …)`.

### 9. `DESCRIPTION` Description — quote software name
`dmdDataLoader` is a tool name and should be single-quoted (`'dmdDataLoader'`)
per CRAN convention. (Title, length, sentence count, and the no-forbidden-opening
rule are all fine.)

## Low priority (recommended)

- **`R/dmd_dose_optimise.R:976` — fragile warning de-duplication.**
  `dmd_dose_cost_range()` dedupes the "unsupported compound" warning by
  `grepl()`-ing the message text emitted in `.drop_unsupported_compounds()`.
  Reword that message and the dedup silently breaks. Emit the warning with a
  custom condition `class` (`cli::cli_warn(…, class = "dmdprices_unsupported_compound")`)
  and filter on `inherits()` instead.
- **`@importFrom memoise memoise cache_memory`** (`R/dmdprices-package.R:56`) —
  `cache_memory` is never used (the code uses `cachem::cache_mem`). Drop it.
  Requires re-running `devtools::document()` to update `NAMESPACE`.
- **`\dontrun{}` over-use.** `dmd_dose_optimise` (`:404`), `dmd_dose_cost`
  (`:692`), `dmd_dose_cost_range` (`:928`) wrap examples that run against the
  bundled `dmd_master` (no network needed) in `\dontrun{}`. The skill says use
  `\dontrun{}` only when an example truly cannot run; prefer un-guarded (or
  `\donttest{}` if >5s). Keep `\dontrun{}` only around the literal
  `dmd_load("~/…")` snippets. *Verify example runtime before changing.*
- **`README.md:16` — add CRAN install line** (`install.packages("dmdprices")`)
  once/if the package is on CRAN; keep the `install_github` line for the dev
  version.
- **`print.dmd_dose_combination()`** (`R/dmd_dose_optimise.R:1037+`) uses `cat()`.
  Defensible for a print method, but `cli::cli_verbatim()`/`cli::cli_text()`
  would match the package's stated convention.
- **`helper.R` fixture** — `.fake_dose_db()` is well-built, but `loaded_at =
  Sys.time()` is non-deterministic and would break any future whole-db snapshot;
  use a fixed timestamp. `.codeine_db()` lives in a test file rather than
  `helper.R`.
- **URLs** — all `https://`. Run `urlchecker::url_check()` before any CRAN
  submission (the National Archives OGL link occasionally redirects).
